# ADR-0110: the `29 /r` register/register `sub` at three widths

- Status: accepted
- Date: 2026-11-09
- Settles: `X86-P80` (the three register/register `sub` rows and their byte
  vector)
- Supersedes: none
- Superseded by: none
- Revises: `EC-42` of `02_encoding_choices.md` (new row: the `29`/`2B`
  direction choice); the reading-aid table and `0.74.0` paragraph of
  `07_definition_format.md` §8.1; the x86 table of `06_validation_matrix.md`;
  repoints the `N01ej` fixture; adds `definitions/x86_64/0.74.0.json`,
  `EXP-0111` and the `X86-P80`/`N01et`/`N02dc`/`N14cg` fixtures

## Context

`0.66.0` (`X86-P72`) gave `sub` its three immediate forms (`REX.W 83 /5 ib`,
`REX.W 81 /5 id`, `REX.W 2D id`). No register/register row exists, so a plan
that wants `sub %rcx, %rax` has no form to name.

`29 /r` and `2B /r` are different directions: `29` writes the `ModRM.r/m`
operand, `2B` writes the `ModRM.reg` operand. At register/register both are
legal and assemblers choose `29`; the choice is a byte-affecting decision, so
`EC-42` names it and the plan carries the row rather than a flag.

`EXP-0111` measures all six combinations:

- `subq %rcx, %rax` = `48 29 c8` (3 B), `subq %rax, %rcx` = `48 29 c1`;
- `subl %ecx, %eax` = `29 c8` (2 B), `subl %eax, %ecx` = `29 c1`;
- `subw %cx, %ax` = `66 29 c8` (3 B), `subw %ax, %cx` = `66 29 c1`.

`ModRM = c8` is `reg = 1`, `r/m = 0`, so the two fields move independently.
`REX.W`/`0x66` are template content; the register fields are three bits.

## Decision

1. **Three new rows.** `0.74.0` appends
   `x86:sub/rm64-r64/legacy` (`4829c8`), `x86:sub/rm32-r32/legacy`
   (`29c8`) and `x86:sub/rm16-r16/legacy` (`6629c8`), one per value width.
   The naming follows the existing `x86:mov/rm-r64/legacy` pattern: the
   destination is the `r/m` field, the source is the `reg` field.
2. **Slots are the measured ones.** Destination `x86.gpr64`/`rm64` at
   `[0,1]` (`REX.B`) and `[16,3]` (`ModRM.r/m`) on the 64-bit row, or just
   `[16,3]` at 32/16 bits; source `x86.gpr64`/`r64` at `[2,1]` (`REX.R`) and
   `[19,3]` (`ModRM.reg`), or just `[19,3]`. The 32-bit row is a two-byte
   template, so its `ModRM` sits at `[8,3]`/`[11,3]`.
3. **Low register window only.** Both fields are three bits, so `%r8`-`%r15`
   would need `REX.R`/`REX.B` and is deferred. Those rows change the template
   and are a separate slice.
4. **The memory-destination direction stays absent.** `2B /r` (including its
   register/register spelling) is not added; `N01ej` is repointed to name it
   against `0.74.0`, so the deliberate absence has a vector.
5. **`0.74.0` is additive and immutable.** It repeats the 561 `0.73.0` forms
   byte-for-byte, and the generator asserts the reproduction before it writes
   the new version. The digest is
   `sha256:27f337115cffe89c8d7028863e7748783247344ba4d8e622fa9c4345efdead58`.

## Consequences

- `X86-P80-sub-rr` is the 16-byte vector of six instructions, no label and no
  relocation. The input hash is
  `7a4aa6fd42e25efb54043a8f22bc58e44aed4138e278a741313618ad014d813c` and the
  output hash is
  `6a77edb61cdf1b27a46c014a1f31cf59ab5204e26eb720460e5e9886fcef6ccf`.
- `N01et` pins the `0.73.0` boundary, `N01ej` the absent `2B` direction,
  `N02dc` the operand count (`expected: 2`, `found: 1`) and `N14cg` the
  three-bit field end (`field_bits: 3`).
- The corpus grows to 121 positives and 586 negatives; every one of the 564
  forms in `0.74.0` is named by a positive fixture (`check_definition.py`).
- `0.73.0` remains readable and unchanged, so a plan pinned to it cannot name
  the new rows and keeps its old byte behaviour.

## Alternatives rejected

- **Add `2B /r` as the register/register row.** Rejected: GAS/`llvm-mc` emit
  `29` for register/register, and `2B` is the memory-destination direction;
  picking it would make the row disagree with every assembler and with the
  measured bytes.
- **One row with a `direction` modifier.** Rejected: the opcode byte is
  template content and a modifier must not write a template byte (`EC-41`
  reached the same conclusion for `b`/`bl`).
- **Add the high register window now.** Rejected: `REX.R`/`REX.B` change the
  template byte, so the length/bytes would depend on the operand (`INV-04`).
- **Add the memory shapes (`ModRM.mod != 11`) too.** Rejected: they introduce
  `SIB`/displacement decisions (`EC-37`) that this slice does not measure.

## Review triggers

- The `2B /r` direction is proposed; it needs its own rows and byte vector.
- The high register window is proposed; `REX.R`/`REX.B` change the template.
- A memory shape (`ModRM.mod != 11`) is proposed; it adds `SIB`/displacement
  decisions and a different length.
- Another ALU mnemonic is proposed; the opcode byte changes and must be
  measured, not copied from `sub`.
