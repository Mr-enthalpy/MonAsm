# ADR-0102: the direct `call rel32` row is a form, not a link modifier

- Status: accepted
- Date: 2026-11-08
- Settles: `X86-P73` (the direct `call rel32` row: `E8 cd` with the target at
  `[8,32]`)
- Supersedes: none
- Superseded by: none
- Revises: `EC-03` (the rel8/rel32 pair is a `jmp` property; `call` is
  rel32-only, and the indirect `FF /2` family is a separate decision); the
  x86-64 slice table of `02_encoding_choices.md`; the x86 table of
  `06_validation_matrix.md`; adds `definitions/x86_64/0.67.0.json` and the
  `X86-P73` fixture

## Context

The table has had `x86:jmp/rel8/legacy` (`EB cb`) and `x86:jmp/rel32/legacy`
(`E9 cd`) since `0.1.0`. No version has a form whose `form_id` contains
`call`: the 512-form canonical `0.66.0` table returns zero matches, and every
earlier document is a subset of it, so a plan that names a direct call is
`E-FORM-001` today.

A direct call is the `jmp rel32` row with the opcode byte changed: `callq` is
`E8 cd`, and the field is the displacement from the end of the instruction.
`EXP-0103` measures the whole surface with `llvm-mc`/`llvm-objcopy` 23.1.2 on
2026-11-08:

| Source | Bytes | Length | Shape |
|---|---|---|---|
| `callq L1` | `e8 05 00 00 00` | 5 | local symbol, resolved in place |
| `callq ext` | `e8 00 00 00 00` | 5 | external symbol, one relocation |
| `call .+130` | `e8 7d 00 00 00` | 5 | literal field value `125` |
| `addq $1, %rax` | `48 83 c0 01` | 4 | the `0.1.0` row that hosts `L1` |

Three facts decide the row:

1. **The displacement is measured from the end of the instruction.** `L1` is
   at offset 10 and the instruction ends at offset 5, so `callq L1` writes
   `+5`. `pcrel_begin` would write `+10`. The measured byte is `05`, which is
   `pcrel_end` with addend 0.
2. **An external target is a relocation, not an address.** `callq ext`
   writes zero and `llvm-readobj --relocations` reports
   `0x6 R_X86_64_PLT32 ext 0xFFFFFFFFFFFFFFFC`. Addend `-4` from the end of
   the instruction is the same value the plan states as `pcrel_end` with
   addend 0 (`X86-P8` already makes that argument for `jmp ext`).
3. **The indirect call is a different encoding of the same source
   operation.** `callq *%rax` is `ff d0`, `callq *(%rax)` is `ff 10` and
   `callq *8(%rax)` is `ff 50 08`: the `FF /2` group has a `ModRM` byte and a
   register-or-memory operand, while the direct row has neither. One is not a
   longer spelling of the other.

## Decision

1. **`0.67.0` appends exactly one row:**

   | `form_id` | Template | Slots |
   |---|---|---|
   | `x86:call/rel32/legacy` | `e800000000` | `target` `x86.rel`/`rel32` → `[8,32]` |

   The slot is the `jmp/rel32` slot unchanged: `from: operand_value`, range
   `{signed: true, bits: 32, align_bits: 0}`. The opcode byte `E8` is
   template content.
2. **There is no `link` field and no rel8 variant.** The mnemonic and the
   opcode byte are implied by `form_id`; a plan field that chose between `E8`
   and `E9` would be implicit instruction selection (`INV-01`, `INV-02`).
   `call` has no `rel8` encoding on x86-64, so `EC-03`'s width pair does not
   apply to it and no second row is invented.
3. **The target operand is `x86.rel`, never a register.** A symbol payload
   plus one fixup over `[8,32]` is the relocation form; a `payload.value` is
   the literal displacement. A `x86.gpr64` operand is `E-OPERAND-001` on both
   the kind and the target type (`N02cu`), and a missing target is
   `E-OPERAND-002` (`N02cv`).
4. **A symbol target uses `pcrel_end` with addend 0.** `resolve_in_place`
   writes `S + A − P` with `P` at the instruction end; `emit_relocation`
   records the reference and leaves the field zero, which is the
   `R_X86_64_PLT32 ext -4` case. The rule is not a modifier: the same row is
   used for both, and the plan's `resolution_mode` decides.
5. **The indirect `FF /2` family stays absent.** Naming
   `x86:call/rm64/legacy` is `E-FORM-001` (`N01el`); the id appears in no
   definition document, because the indirect call needs its own operand
   geometry and its own fixture. Naming a `0.67.0` row against `0.66.0` is
   also `E-FORM-001` (`N01em`), which pins the version boundary.
6. **No schema, loader or materializer change.** Every slot kind, placement,
   range and operand role used here already exists; only the definition table
   grows. `0.66.0` is unchanged; `0.67.0` has 513 forms with digest
   `sha256:367d76ebf89ee9c1cf51f561b4798eeb0a2000ae3688ee9a52a4c4a9eaea5c9e`.

## Consequences

- `X86-P73-call-rel32` is four instructions and 19 bytes: the local call, the
  external call, the `addq` that hosts `L1`, and the literal-displacement
  call. Its `expected.bin` comes from `llvm-mc` + `llvm-objcopy`, never from
  the materializer; the oracle's `input_sha256` is
  `a282dfc425ca43038f9aa4a43b822ec4a32f290f1e77a576c3f2658498d2a90c`
  (`probe.asm`) and its `output_sha256` is
  `0f9014099643ce792b93e64482d630ddee32310657e46211a1ab6aa9276521fb`
  (the 19-byte `.text`).
- Five negatives pin the shape: the indirect sibling (`N01el`,
  `E-FORM-001`), the version boundary (`N01em`, `E-FORM-001`), a register
  operand (`N02cu`, `E-OPERAND-001` twice), a missing target (`N02cv`,
  `E-OPERAND-002`) and a displacement past the signed 32-bit end (`N04g`,
  `E-RANGE-002`).
- `EC-03` is revised in place: it now states that `call` is rel32-only and
  that the indirect family is a separate decision. No `EC` row is added or
  renumbered.
- The x86 slice table gains the row, the x86 fixture README gains `X86-P73`,
  and `07_definition_format.md` §8.1 gains the row, the header range
  `0.1.0` … `0.67.0` and the new digest.

## Alternatives rejected

- **A `rel8` call.** Rejected: x86-64 has no short direct call. `E8` is the
  only form, so a 2-byte call would have to be an invented instruction.
- **Reuse `jmp/rel32` with a `link` or `opcode` modifier.** Rejected: the
  difference is the opcode byte, which is instruction selection. A field that
  carried it would also have to distinguish `E8` from `E9`, `EB`, `E3` and the
  conditional jumps.
- **Fold the indirect call into the same row with an operand-kind switch.**
  Rejected: `FF /2` needs a `ModRM` byte and a register-or-memory operand, so
  the two encodings have different lengths and different slot geometry.
  Selecting between them by operand kind is implicit instruction selection
  (`INV-01`, `INV-02`).
- **Resolve an external symbol to an absolute address.** Rejected: the
  materializer does not link. `emit_relocation` records the reference; the
  linker decides the final value.
- **Select `pcrel_begin` because `call .+130` looks like a distance from the
  instruction start.** Rejected: the source expression is llvm-mc's syntax,
  not the field. The field is `130 − 5 = 125`, and `callq L1` at offset 0
  with `L1` at 10 is `+5`, both of which are `pcrel_end`.

## Evidence status

| Claim | Basis | Confidence |
|---|---|---|
| the direct row is `E8 cd` with the field at `[8,32]` | `llvm-mc -show-encoding` and object bytes, `EXP-0103` §1 | high |
| `callq L1` writes `+5` when `L1` is at offset 10 | object bytes plus the `0.67.0` slot placement, `EXP-0103` §1 | high |
| `callq ext` carries `R_X86_64_PLT32 ext -4` | `llvm-readobj --relocations`, `EXP-0103` §1 | high |
| `call .+130` writes the literal field `125` | object bytes, `EXP-0103` §1 | high |
| the indirect forms are `ff d0` / `ff 10` / `ff 50 08` | `indirect.asm` object bytes, `EXP-0103` §2 | high |
| `0.66.0` has no `call` form | `definitions/x86_64/0.66.0.json`, form-id scan | high |
| `2147483648` on the signed displacement is `E-RANGE-002` | `N04g` run through the fixture gate, `EXP-0103` §4 | high |

## Review triggers

- An indirect call (`FF /2`), a register call or a memory call is proposed;
  each needs its own operand geometry and its own fixture.
- A 16- or 32-bit operand-size call (`66 E8`, `67 E8`) is proposed; the
  prefix and the address-size interaction need their own measurement.
- A symbol in the `call` displacement is proposed for a target other than a
  symbol operand; the relocation class is already measured, but a second
  field shape would need its own evidence.
- A plan asks for `lcall`, `syscall` or another instruction that reuses `E8`
  with a different reading.
